# iKEAP-platform 软件功能模块大纲

## 1. 产品目标与范围

建设前后端分离的工业软件云平台，以知识、模型、数据和资源协同闭环组织工业任务，覆盖资源接入、数据治理、知识检索、方案推理、工程验证、软件服务调用和执行反馈。

平台由六个核心业务模块及共用平台能力组成。六个模块在前后端使用相同目录名称，可以独立开发、统一集成。当前文档为功能设计，不表示相关功能已经实现。

### 1.1 主要使用角色

| 角色 | 主要操作 |
| --- | --- |
| 平台管理员 | 用户权限、空间配置、资源登记、服务配置、审计管理 |
| 知识工程师 | 实体关系维护、知识导入、图谱审校、检索评估 |
| 工艺工程师 | 工艺规划、候选方案比选、刀路生成、仿真审核 |
| 运维工程师 | 设备监测、异常分析、故障诊断、维护计划 |
| 服务开发人员 | 服务注册、适配器配置、Agent能力维护、流程调试 |
| 项目负责人 | 项目管理、成果审核、任务追踪、报告查询 |

## 2. 四层功能架构

| 层级 | 职责 | 主要内容 |
| --- | --- | --- |
| 资源层 | 连接与管理工业资源 | 设备、软件、计算资源、数据源、文件、工艺与故障资料 |
| 使能层 | 为业务提供可复用能力 | 数据治理、知识图谱、检索、模型调用、规则验证、资源能力匹配 |
| 驱动层 | 将能力组织为可执行任务 | 任务解析、Agent能力描述、服务发现、调度、流程执行、状态与反馈管理 |
| 应用层 | 提供工程业务入口 | 叶盘CAM、数控机床PHM、任务工作台、结果与报告 |

架构层级描述系统职责；六个功能模块描述开发边界，一个业务模块可以使用多个层级的能力。

### 2.1 统一工业任务流程

任务提交 → 任务解析 → 资源与数据准备 → 知识检索 → 候选方案生成 → 工业约束验证 → 服务编排与工程执行 → 结果审核 → 反馈记录。

每次运行关联任务编号、项目空间、输入版本、知识版本、模型配置版本、规则版本、服务版本和执行记录。验证不通过时，进入有次数上限的修正流程或人工处理；反馈形成待审核记录，经审核后更新知识、规则或服务配置。

## 3. 模块一：工业知识图谱与GraphRAG检索

目录：`knowledge_graph`

### 3.1 功能范围

- 知识源管理：资料登记、文件导入、数据集登记、来源与版本管理。
- 实体管理：实体类型、属性定义、实体录入、别名管理、去重与合并。
- 关系管理：关系类型、方向、属性、关系录入、引用来源与有效期。
- 知识组织：实体关系存储、命名空间、领域子图、版本快照和变更记录。
- 数据治理：字段映射、单位标准化、必填检查、冲突发现、批量导入校验。
- 文档索引：内容解析、分段、来源定位、关键词索引、向量索引与图谱关联。
- 混合检索：关键词检索、向量检索、实体识别与链接、图邻域查询、结果融合。
- 多跳路径检索：起止实体、关系过滤、最大跳数、路径排序、循环控制与结果上限。
- GraphRAG上下文组织：关联文档片段、实体、关系和路径，生成受长度限制的检索上下文。
- 证据整理：证据编号、来源位置、关联实体、路径解释、相关度和引用输出。
- 检索评估：查询样本、期望证据、覆盖率统计、人工反馈和版本对比。

### 3.2 前端页面

知识概览、知识源管理、实体与关系管理、图谱浏览器、检索工作台、路径分析、导入任务、检索评估。

### 3.3 后端能力与数据对象

核心对象：KnowledgeSource、EntityType、Entity、RelationType、Relation、DocumentChunk、GraphSnapshot、RetrievalRequest、EvidenceBundle。

接口范围：`/api/v1/knowledge-graph` 下提供知识源、实体、关系、导入任务、子图查询、检索、路径查询和证据导出。

检索输出统一包含查询编号、结果项、可追溯来源、相关路径、使用的索引版本和检索耗时。缺少证据时返回明确状态。

## 4. 模块二：知识图谱与大语言模型协同推理

目录：`hybrid_reasoning`

### 4.1 功能范围

- 工业任务解析：任务类型、目标、输入参数、约束条件、所需资源和交付物提取。
- 任务模板：工艺规划、故障分析、维护建议等模板及结构化输出约定。
- 上下文构建：任务信息、项目数据、检索证据、规则要求和资源能力整合。
- 证据注入：证据编号保留、来源引用、上下文预算和重复内容清理。
- 模型服务调用：统一适配第三方接口，配置服务地址、模型标识、接口版本、超时和重试。
- 候选方案生成：生成多个结构化方案，保留方案参数、依据、依赖与未确认项。
- 输出处理：结构校验、字段标准化、引用解析、缺失信息识别和失败处理。
- 混合推理：知识检索、候选生成、规则验证和修正组成可追踪的运行流程。
- 方案比较：依据证据完整性、约束通过情况、资源可用性和工程指标比较候选项。
- 过程追溯：记录输入、证据、模板版本、服务配置、输出、工具调用与验证结果。

### 4.2 前端页面

任务解析工作台、上下文与证据预览、候选方案对比、推理运行详情、模板管理、输出结构配置。

### 4.3 后端能力与数据对象

核心对象：ReasoningTask、TaskSpecification、ContextBundle、PromptTemplate、CandidateSolution、ReasoningRun、ModelInvocation。

接口范围：`/api/v1/hybrid-reasoning` 下提供任务解析、上下文预览、运行提交、候选查询、方案比较、修正和运行详情。

服务密钥由后端安全配置管理，不发送给浏览器。第三方调用保留接口与模型版本信息；结构不合法、证据不足或验证未通过的结果不能直接进入工程执行。

## 5. 模块三：工业机理与语义约束验证

目录：`constraint_validation`

### 5.1 功能范围

- 规则库管理：规则分类、适用对象、参数、优先级、版本、启停与审核。
- 语义一致性：类型匹配、关系合法性、术语一致性、上下文一致性检查。
- 参数与量纲检查：单位换算、数值范围、量纲一致性和必要参数检查。
- 资源能力约束：设备行程、加工范围、转速、功率、精度、刀具和软件能力匹配。
- 工业机理验证：按业务调用计算程序或公式模块，记录输入、计算依据和结果。
- 第三方计算适配：任务提交、状态查询、结果获取、超时取消与错误转换。
- 候选方案验证：逐项规则检查、通过/失败/未知状态、问题等级和解释。
- 方案筛选：剔除硬约束不满足的方案，按软约束指标生成比较结果。
- 修正流程：生成修正要求、更新候选版本、重复验证和修正次数限制。
- 验证报告：规则版本、软件版本、检查值、允许范围、结果文件与审查记录。

### 5.2 前端页面

规则管理、约束模板、资源能力检查、验证任务、验证报告、候选筛选、修正记录。

### 5.3 后端能力与数据对象

核心对象：RuleDefinition、ConstraintSet、CapabilityProfile、ValidationJob、ValidationFinding、ValidationReport、CorrectionRecord。

接口范围：`/api/v1/constraint-validation` 下提供规则、约束集、验证任务、验证结果、候选筛选和修正记录。

第三方软件未配置、许可证不可用或结果缺失时标记为未知或失败，不能作为验证通过。报告中的计算结论必须关联实际计算输出。

## 6. 模块四：基于元数据的Agent构建与协同编排

目录：`agent_orchestration`

### 6.1 功能范围

- Agent能力描述：名称、职责、能力标签、输入输出结构、支持协议、服务地址和版本。
- 能力注册与发现：按任务类型、资源需求、可用状态、协议和版本筛选服务。
- Agent配置构建：由元数据关联任务模板、工具、约束策略和运行参数。
- 任务分解：生成任务节点、输入输出映射、依赖关系和交付物要求。
- 流程编排：有向无环任务图、顺序执行、并行分支、条件分支和结果汇聚。
- 任务调度：并发限制、资源占用、优先级、队列、超时和重试。
- 状态管理：任务提交、运行、等待、完成、失败、取消和状态事件。
- MCP工具接入：工具发现、工具描述、参数校验、调用、结果解析和错误处理。
- A2A交互：能力发现、任务发送、消息与产物交换、状态查询、取消和异常处理。
- 人工审核节点：方案确认、工程执行放行、失败处理与流程恢复。
- 执行可靠性：幂等控制、断点恢复、事件去重、失败补偿和运行历史。
- 运行观测：节点耗时、调用日志、输入输出摘要、资源消耗和失败定位。

### 6.2 前端页面

Agent注册中心、能力详情、工具管理、流程模板、流程编排器、任务队列、运行拓扑、人工处理台。

### 6.3 后端能力与数据对象

核心对象：AgentDefinition、CapabilityDescriptor、ToolBinding、WorkflowDefinition、WorkflowVersion、TaskNode、WorkflowRun、TaskEvent、ArtifactReference。

接口范围：`/api/v1/agent-orchestration` 下提供Agent、能力发现、工具绑定、流程定义、流程发布、运行控制和事件查询。

MCP与A2A各设协议适配器，记录实际采用的协议版本、传输方式、认证方式和兼容范围。内部工作流接口与对外协议接口分别实现；跨服务操作校验身份、任务归属和工具授权。

## 7. 模块五：叶盘CAM工作流

目录：`blisk_cam`

### 7.1 功能范围

- 加工项目：零件、材料、毛坯、几何文件、技术要求和项目文件管理。
- 制造资源：机床、刀具、夹具、加工软件和后处理配置关联。
- 工艺规划任务：加工特征、工序顺序、加工策略、工艺参数和约束组织。
- 工艺知识检索：相似工艺、刀具选择、参数范围和加工规则检索。
- 元算法服务调用：算法登记、参数输入、作业提交、进度查询和结果归档。
- 候选工艺方案：方案生成、工序编辑、参数调整、证据查看和比较。
- 刀路生成接口：对接实际CAM软件或刀路服务，传递几何与工艺参数并获取结果。
- 仿真与验证：碰撞、干涉、过切、残留、机床行程和工艺约束检查。
- 程序生成与审核：后处理服务调用、程序版本、校验结果与审核记录。
- 程序分发：目标设备确认、文件校验、分发状态和接收回执。
- 执行反馈：加工开始结束、报警、加工指标、质量结果和工艺修订建议。
- 成果归档：工艺单、刀具单、程序、刀路文件、仿真报告和运行记录。

### 7.2 标准业务流程

项目建立 → 几何与资源准备 → 工艺知识检索 → 候选工艺生成 → 约束验证 → 工艺确认 → 元算法与刀路生成 → 仿真验证 → 程序审核 → 程序分发 → 执行反馈与归档。

### 7.3 前端页面

CAM项目列表、零件与资源配置、工艺规划工作台、工序编辑、算法作业、刀路任务、仿真报告、程序分发、执行反馈。

### 7.4 后端能力与数据对象

核心对象：CamProject、Workpiece、ProcessPlan、OperationStep、AlgorithmJob、ToolpathJob、SimulationJob、NcProgram、DispatchRecord、MachiningFeedback。

接口范围：`/api/v1/blisk-cam` 下提供项目、工艺方案、算法作业、刀路任务、仿真、程序审核、分发和反馈。

CAM、仿真、后处理与机床通信均通过适配器接入，明确所需软件、许可证、接口和文件格式。外部执行采用异步作业；程序分发经过版本确认和工程审核，分发回执与机床执行结果分别记录。

## 8. 模块六：数控机床PHM工作流

目录：`cnc_phm`

### 8.1 功能范围

- 设备台账：机床、部件、测点、额定参数、使用环境和维护历史。
- 数据接入：设备状态、报警、振动、温度、电流等数据接收与批量导入。
- 数据质量：时间对齐、单位转换、缺失值标记、异常值检查和采样信息管理。
- 异常事件：阈值或算法结果接入、事件聚合、去重、分级和处理状态。
- 故障知识检索：按设备、部件、症状、工况和历史事件检索证据。
- 候选原因生成：故障原因、依据、待补充检查项和不确定项整理。
- 诊断规则验证：症状一致性、参数阈值、故障关系、检查结果和资源约束验证。
- RUL预测服务：输入特征、预测调用、结果获取、适用范围和模型版本追踪。
- 维护决策：维护动作、优先级、建议时窗、备件、人员和停机资源需求。
- 维护工单：创建、派发、执行、验收和关闭。
- 反馈更新：实际故障原因、维修动作、恢复结果、诊断评价与知识修订申请。
- 健康报告：设备状态、异常趋势、诊断证据、预测结果和维护记录。

### 8.2 标准业务流程

数据接入 → 异常事件生成 → 故障知识检索 → 候选故障原因生成 → 规则验证与补充检查 → RUL服务调用（满足输入条件时）→ 维护建议 → 工单执行 → 效果评价与反馈。

### 8.3 前端页面

设备总览、设备详情、测点配置、数据质量、异常事件、诊断工作台、健康趋势、RUL预测、维护决策、维护工单。

### 8.4 后端能力与数据对象

核心对象：MachineAsset、ComponentAsset、MeasurementPoint、TelemetryBatch、AnomalyEvent、DiagnosticCase、FaultCandidate、RulPrediction、MaintenanceDecision、MaintenanceOrder、RepairFeedback。

接口范围：`/api/v1/cnc-phm` 下提供设备、测点、数据批次、异常事件、诊断、预测、维护决策、工单和反馈。

RUL服务明确模型来源、版本、输入特征、历史窗口、预测时间基准、输出单位和外部运行依赖。数据不足或超出适用范围时返回不可预测状态；预测区间仅在模型真实提供时展示。

1. 工作台：概览、我的任务、待处理事项。

3. 协同推理：任务解析、候选方案、运行记录、模板。
4. 约束验证：规则、约束集、验证任务、报告。

6. 叶盘CAM：项目、工艺、刀路、仿真、程序、反馈。
7. 机床PHM：设备、异常、诊断、预测、维护。
8. 平台管理：空间、资源、服务、数据文件、权限、审计、配置。

## 11. 技术与集成规划

- 前端：Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia；图谱和流程图组件按实际交互需求选型。
- 后端：Python、FastAPI、Pydantic、SQLAlchemy、Alembic；核心模块采用模块化单体组织，工程计算和长任务通过作业接口异步执行。
- 业务存储：MySQL保存用户、任务、配置、版本、报告与业务记录。
- 图存储：实体、关系与文档统一保存在MySQL，通过知识模块实现有界路径查询。
- 检索存储：初期采用MySQL持久化与字符片段相似度检索，后续按规模接入全文与向量索引。
- 时序数据：按数据规模选择分区表或时序扩展，原始大文件单独存储。
- 队列与缓存：当前使用单进程Python后台任务；业务状态持久化到MySQL，分布式队列作为后续扩展。
- 文件存储：本地开发存储适配器和兼容S3的生产存储适配器。
- 接口：REST管理与查询、SSE任务事件推送、独立MCP与A2A适配器。
- 部署：前端静态资源、后端接口、任务执行器、数据库及外部服务分开配置。

具体依赖版本在开始实现时确认并锁定；开源依赖保留许可证与必要版权声明。

## 12. 完整交付内容与实现顺序

### 12.1 交付内容

前后端源码、数据库迁移、初始化数据、接口说明、外部服务适配器、示例工作流、验证样例、配置模板、部署配置、运行说明和必要的自动化检查。

示例数据标明用途；外部服务演示模式与真实连接模式有明确配置和运行标识。真实工程执行结果由实际服务返回。

### 12.2 实现顺序

1. 平台基础：工程初始化、权限、项目空间、数据库、文件、资源和服务配置。
2. 知识与验证：知识导入、实体关系、GraphRAG检索、证据输出、规则与验证报告。
3. 推理与编排：任务解析、模型适配、候选方案、修正闭环、Agent元数据、调度、MCP与A2A。
4. CAM贯通：工艺规划、算法、刀路、仿真、程序审核、分发与执行反馈。
5. PHM贯通：数据接入、异常、诊断、规则验证、RUL、维护工单与反馈。
6. 工程完善：权限核验、异常恢复、性能检查、部署验证、使用文档和成果导出。

### 12.3 验收要点

- 六个模块均有独立前后端目录、页面入口与服务接口。
- 检索结果能定位到来源，推理方案能关联证据与验证报告。
- 规则失败、服务离线、超时、取消和重复提交均有明确处理。
- 编排任务能追踪节点输入输出、协议调用、状态事件和运行产物。
- CAM与PHM分别完成一次可追溯的业务闭环。
- 外部软件与模型服务说明接口、版本、依赖、配置及接入限制。
- 工程计算、刀路、仿真、RUL和设备反馈的结果可区分实际服务输出与演示数据。
